# abc-library 기능 명세

## 화면

모든 화면 위쪽에 검색창이 있다. 제목, 저자, 태그에서 대소문자와 공백을 무시하고 찾으며, 입력하는 동안 HTMX로 결과를 바꾼다.
휴대폰에서는 브랜드와 검색창이 한 줄에 있고, 메뉴는 그 아래에서 옆으로 밀리는 탭 줄이다.

색은 역할을 나눠 쓴다. 파란색은 링크와 누를 것, 빨간색은 '새 책', 노란색(형광펜)은 소식에서 눌러 온 이야기 묶음에만 쓴다. 표지는 어느 화면에서나 왼쪽에 책등 그림자를 얹고, 표지가 없는 책(또는 교보문고에 그림이 없는 책)은 제목을 쓴 파란 천 표지로 그린다.

### 홈: 타임라인

- 최근 소식을 시각의 역순으로 보여 준다. 같은 글의 본문과 댓글이 같은 책을 다뤘으면 소식 하나로 묶는다.
- 소식은 두 종류다.
  - 새 책: 처음 언급된 책이 등록됐다.
  - 이야기 추가: 이미 등록된 책이 다른 글이나 댓글에서 다시 언급됐다.
- 소식은 SNS 글처럼 그린다. 머리에 종류 아이콘(새 책은 빨간 책, 이야기 추가는 파란 말풍선)과 시각, 몸통에 그 글이 책에 대해 한 이야기의 요약 앞부분(세 줄, 최대 120자), 그 아래에 책(표지, 제목, 저자, 태그)을 붙이고, 발에 그 글의 댓글 중 이 책을 다룬 수(있을 때만)와 이 책의 모든 이야기 수를 둔다. 소식 전체가 책 상세로 연결된다. 요약은 본문 언급이 있으면 그것을, 없으면 첫 댓글 언급을 쓴다.
- 시각은 서버가 날짜로 그리고, 브라우저가 일주일 안의 소식은 '3시간 전'처럼, 올해 소식은 연도를 빼고 바꾼다(`static/app.js`). 책 목록의 마지막 언급일도 같다.
- 휴대폰에서는 소식을 화면 너비에 붙이고 회색 틈으로 나눈다. 넓은 화면에서는 가운데 한 줄(640px)로 둔다.
- 새 책 소식은 책 상세의 처음으로, 이야기 추가 소식은 책 상세에서 그 글의 언급 묶음(`#post-{post_no}`)으로 바로 스크롤해서 열고, 그 묶음의 테두리를 강조하고 형광펜 색을 잠깐 칠한다.
- 다음 페이지는 '더 보기'가 화면에 들어오면 HTMX로 이어 붙인다. 누를 수도 있다.

### 책 목록

- 표지 썸네일, 제목, 저자, 다룬 게시글 수, 마지막 언급일을 격자로 보여 준다.
- 태그(`?tag=`), 저자(`?author=`), 검색어(`?q=`)로 거를 수 있다.

### 책 상세

- 위쪽에 표지, 제목, 저자, 출판사, 태그, 교보문고 구매 링크를 둔다.
  - 구매 링크는 교보문고 상품 페이지다. 상품을 확정하지 못한 책은 교보문고 검색 결과로 연결한다.
- 아래쪽에는 이 책에 대한 언급을 댓글처럼 모아 보여 준다.
  - 게시글별로 묶는다. 본문 언급이 있으면 그것을 위에 두고, 그 글의 댓글 언급을 아래에 답글처럼 세로선에 매달아 붙인다. 댓글에서만 다룬 글은 댓글 언급만 보인다.
  - 각 언급에는 날짜, AI 요약, 그 언급에 들어 있던 링크를 넣는다. 묶음마다 밴드 원문 링크를 둔다.
  - 요약은 개인 정보를 뺀 것이다. 원문과 작성자 이름은 보여 주지 않는다.
  - 원문 링크 형식은 `https://band.us/band/102765569/post/{post_no}`이다. 비공개 밴드라서 멤버만 열어 볼 수 있다.

### 태그, 저자

- 태그 화면은 모임 주제를 정한 순서로 먼저 보여 주고, 그 밖의 태그를 책 수 순서로 보여 준다.
- 저자 화면은 저자와 책 수를 보여 준다. 누르면 책 목록으로 거른다.

### 로그인과 북마크

- 누구나 Google 계정으로 로그인해서 관심 있는 책을 북마크한다. 위쪽 메뉴의 '로그인'을 누르면 Google로 넘어가기 전에 무엇을 저장하는지 알리는 화면(`/login`)을 먼저 보여 준다.
- 사용자 로그인은 Google에 범위 `openid`만 요청하므로 메일 주소를 받지 않는다. 사용자는 Google 계정 고유 번호(sub)를 `USER_ID_SECRET`으로 HMAC-SHA256한 값(`users.subject_hash`)으로만 구별하고, 이름, 메일 주소, 프로필은 저장하지 않는다.
  - sub는 Google이 계정마다 바꾸지 않고 다시 쓰지 않는 번호라서 메일 주소보다 식별자로 알맞다. 메일 주소는 바뀌거나 다른 사람에게 다시 배정될 수 있다.
  - 메일 주소의 HMAC 값은 함께 저장하지 않는다. 쓸 데가 없고, 메일 주소는 짐작하기 쉬워서 키가 새면 맞춰 볼 수 있다.
- 책 상세에서 북마크하고, 그 책을 넣을 내 카테고리를 여러 개 고른다. 북마크한 책은 제목 아래에 '북마크함'과 넣은 카테고리가 바로 보인다.
- 북마크와 카테고리는 따로다. 카테고리를 하나도 고르지 않은 북마크는 내 북마크에만 있고 공개 화면에는 나오지 않는다. 이것을 예상할 수 있게 다음 세 곳에서 알린다.
  - 책 상세의 북마크 패널: 카테고리 고르기 아래에 고른 카테고리에만 넣는다는 안내를 둔다.
  - 저장한 뒤: 카테고리를 고르지 않고 저장했으면 공개한 카테고리에는 나오지 않는다고 알린다(`done=bookmark-saved-alone`).
  - 내 북마크: 카테고리가 하나라도 있는 사용자에게 카테고리 밖의 북마크 수를 알리고, 그 책의 표지 아래 '카테고리 없음'을 빨간 글씨로 쓴다.
- 내 북마크(`/me`)에서 카테고리를 만들고 북마크를 모아 본다. 북마크는 최근에 북마크한 책이 먼저 나오고, 여기서는 순서를 바꾸지 않는다. 카테고리는 사용자마다 100개까지 만든다. 카테고리는 ↑↓로 순서를 바꾸고, 책 상세의 카테고리 고르기와 '북마크함' 표시도 그 순서를 따른다. 새 카테고리는 맨 뒤에 온다. 계정을 지우면 북마크와 카테고리가 모두 지워진다.
- 카테고리(`/me/categories/{id}`)에는 제목, 본문(여러 줄, Markdown), 공개용 제목, 공개 여부가 있다. 카테고리 화면에서 책을 ⠿로 끌어서(키보드로는 ⠿에서 방향키로) 그 카테고리 안의 순서를 바꾸고, 공개 화면도 이 순서를 따른다. 순서는 카테고리마다 따로이고, 카테고리에 새로 넣은 책은 맨 앞에 온다. 끌기는 마우스와 터치를 함께 다루려고 포인터 이벤트로 만들었다(`static/app.js`). 본문의 원시 HTML과 `javascript:` 같은 위험한 주소는 싣지 않는다(goldmark 기본값).
- 공개한 카테고리는 짧은 주소 `/shared/{code}`에서 누구나 공개용 제목(비었으면 제목), 본문, 책 목록을 한 화면에 본다. `code`는 임의로 뽑은 영어 소문자 3자(17,576 가지)다. 겹치면 다시 뽑고, 열 번 겹치면 한 글자 더 긴 코드를 뽑는다. 대문자로 적은 주소도 찾는다. 공개하지 않은 카테고리는 만든 사람에게만 보인다.
- 공개 주소에는 카카오톡 같은 메신저의 링크 미리보기를 위한 og 태그를 둔다. 제목은 공개용 제목, 설명은 본문의 글자 앞부분(본문이 없으면 앞의 책 세 권의 제목), 그림은 표지가 있는 첫 책의 교보문고 표지(없으면 앱 아이콘), `og:url`은 소문자 코드의 공개 주소다. 카카오는 미리보기를 한동안 캐시하므로, 바로 바꿔 보려면 카카오 개발자 도구의 캐시 초기화를 쓴다.
- 위쪽 메뉴의 '공개 북마크'(`/shared`)는 모든 사용자의 공개한 카테고리를 최근에 고친 순서로 보여 준다.
- 카테고리 편집 화면(만든 사람만 본다)에는 '이 사이트에 없는 새로운 책을 추가하고 싶다면 밴드에서 책에 대한 글을 써주세요. 1일 이내에 이 사이트에 책이 추가됩니다.'라는 안내를 둔다. 공개 화면에는 두지 않는다.
- 북마크한 책은 배치가 다시 추출해서 언급이 없어져도 지우지 않고, 관리자가 책을 합치면 합친 책으로 옮긴다. 관리자가 언급을 모두 지운 책은 북마크 목록에서 보이지 않는다.

### 도움말

- 위쪽 메뉴의 맨 끝과 모든 화면 아래쪽에서 도움말(`/help`)로 연결한다. 원본은 `internal/web/templates/help.html`이다.
- 최근 소식, 책 찾기, 책 화면, 북마크, 새 책 올리기, 휴대폰에 설치하는 방법을 설명한다.
- 화면 설명에는 휴대폰 크기(390×760, 2배율)로 찍은 캡처를 밝은 화면과 어두운 화면 한 쌍씩 WebP로 넣는다(`static/help/`). 보는 사람의 테마에 맞는 쪽을 `<picture>`로 고른다.
  - 캡처는 가상의 데모 데이터로 찍는다. 책 서지 정보는 실제여도 되지만 요약, 댓글, 북마크는 지어낸 것을 쓴다. 실제 밴드 요약이 담긴 화면은 넣지 않는다.
  - 캡처에 나온 화면을 바꾸면 캡처도 다시 찍는다.
- 휴대폰 설치 방법은 Android Chrome(⋮ → 설치 및 바로가기 만들기 → 설치)과 iPhone Safari(⋯ → 공유 → 홈 화면에 추가 → 웹 앱으로 열기, 추가)의 화면을 SVG로 그리고 누를 곳을 파란 고리로 표시한다. 브라우저 메뉴 문구가 바뀌면 그림과 설명을 함께 고친다.

### 개인정보 처리방침

- 모든 화면 아래쪽과 로그인 화면에서 개인정보 처리방침(`/privacy`)으로 연결한다. 원본은 `internal/web/templates/privacy.html`이다.
- 처리하는 정보, 보유 기간, 처리 위탁과 국외 이전(Google, Neon, Anthropic), 쿠키를 바꾸는 작업은 이 화면도 함께 고치고 시행일을 바꾼다.

### 앱 설치(PWA)

- 휴대폰과 데스크톱 브라우저에서 앱으로 설치할 수 있다. 매니페스트는 `/manifest.webmanifest`, 서비스 워커는 `/sw.js`다(원본은 `internal/web/pwa/`).
- 서비스 워커는 정적 파일을 캐시에서 먼저 꺼내고, 화면은 네트워크에서 먼저 받는다. 열어 본 화면(최근 50개)은 연결이 없을 때 캐시로 보여 주고, 처음 여는 화면은 오프라인 안내(`/offline`)를 보여 준다.
- 관리 화면, 내 북마크, 로그인 흐름, 로그인한 사람에게 보인 화면(`Cache-Control: no-store`)은 캐시하지 않는다.
- 정적 파일이나 서비스 워커가 바뀌면 `/sw.js`의 VERSION이 바뀌어서 브라우저가 새 워커를 설치하고 예전 캐시를 지운다.

### 관리

관리자는 화면 아래쪽의 '관리자 로그인'으로 Google 계정에 로그인한다. 관리자 로그인만 범위 `openid email`로 메일 주소를 받아서 관리자 목록과 맞춰 본다. 관리자 목록에 있는 계정만 들어갈 수 있고, 처음 관리자는 benelog@gmail.com이다. 로그인하면 위쪽 메뉴에 '관리'가 생기고 책 상세에 편집 링크가 붙는다. 관리자도 사용자로 함께 로그인해서 북마크를 쓴다.

- 태그(`/admin/tags`): 태그를 더하고, 이름을 바꾸고, 순서를 옮기고, 지운다. 모임 주제는 맨 앞에, 갈래는 맨 뒤에 더한다. 이름을 바꾸거나 지우면 책에 붙은 태그도 함께 바뀐다.
- 책(`/admin/books/{id}`): 제목, 저자, 출판사, ISBN, 교보문고 상품 번호, 태그를 고친다. 목록에 없는 태그는 이름과 갈래를 적어서 저장하면 태그 목록에 더하면서 이 책에 붙는다. 대소문자만 다른 태그가 이미 있으면 그 태그를 붙인다. 같은 책이 둘로 나뉘었으면 다른 책으로 합친다. 책이 아닌 것을 잘못 뽑았으면 언급을 모두 지워서 목록에서 뺀다.
- 언급(`/admin/mentions/{id}`): 요약과 링크를 고치고, 다른 책으로 옮기고, 지운다.
- 관리자(`/admin/admins`): 관리자를 메일 주소로 더하고 뺀다. 자기 자신과 마지막 관리자는 뺄 수 없다.

관리자가 고친 내용은 배치가 같은 글을 다시 추출해도 남는다.

- 고친 책의 정보와 태그는 배치가 바꾸지 않는다. 예전 제목과 ISBN은 같은 책을 찾는 키로 남아서 다시 추출한 결과도 그 책에 모인다.
- 고친 언급은 지우지 않고, 같은 본문이나 댓글에서 같은 책에 대한 새 언급을 더하지 않는다.
- 지우거나 옮긴 언급은 원래 책에 지운 언급으로 남아서 배치가 되살리지 않는다. 언급을 모두 지운 책은 목록에서 사라지고 관리자에게만 보인다. 다른 글에서 새로 언급되면 다시 나타난다.

## 일일 배치

1. 밴드에서 지난 수집 이후 새로 올라온 글, 지난 실행에서 처리하지 못한 글, 최근 7일 사이 글 중 본문이 수정되거나 댓글이 달린 글을 읽는다. 접힌 이전 댓글은 펼쳐서 읽는다.
   - '지난 수집'의 기준은 저장된 게시글 번호의 최댓값이다. 처리하지 못한 글은 `pending_posts`에 남겨서 최대 5번까지 다시 시도한다.
2. 내용(본문, 링크, 사진, 댓글)이 바뀐 글만 Claude에 보낸다. Claude는 본문, 링크, 첨부 사진, 댓글로 책을 찾고, `search_kyobo` 도구로 교보문고를 검색해서 ISBN을 고르고, 책마다 본문 언급과 댓글 언급의 요약을 만든다.
   - 댓글이 본문의 책에 대한 것인지, 댓글에서 새로 소개한 다른 책에 대한 것인지는 Claude가 판정한다.
3. 코드는 Claude의 결과를 검증하고 보탠다.
   - 교보문고 검색 결과에 없던 ISBN, 정해진 목록 밖의 태그, 없는 댓글 번호는 버린다.
   - 언급에 들어 있던 링크를 서점 구매 링크와 Claude가 그 책과 직접 관련이 없다고 판정한 링크(지도, 행사 안내, 그 책을 다루지 않은 기사 등)만 빼고 모두 붙인다. 본문이 책 한 권만 다뤘으면 본문 링크는 모두 그 책의 본문 언급에 붙이고, 여러 권을 다뤘으면 Claude가 고른 번호를 따른다. 댓글 링크는 그 댓글의 언급에 붙인다.
4. 책과 언급을 저장한다. 수정된 글은 그 글의 언급을 새 결과로 바꾸고, 어느 언급에도 남지 않게 된 책은 지운다. 관리자가 고친 책과 언급은 그대로 둔다('관리' 참고).

같은 게시글을 여러 번 처리해도 결과가 같아야 한다. 한 번에 추출하는 게시글 수에는 상한(기본 30)을 둔다.
실행마다 `batch_runs`에 실행 전 마지막 글, 밴드 최신 글, 처리 건수, 오류를 남긴다. `make status`로 최근 실행과 다시 시도할 글을 본다.
프롬프트나 태그 목록을 바꾼 뒤에는 `-redo-from 1`로 저장한 글을 다시 추출한다. 몇 개 글만 고칠 때는 `-redo-posts 175,184`처럼 글 번호를 준다. 이때 `-recheck-days 0`을 함께 주면 최근 글은 다시 읽지 않는다.

## 태그

- 책 한 권에 태그를 1~5개 단다. 태그 목록은 `tags` 테이블에 있고 관리 화면에서 고친다. 배치는 실행할 때 이 목록을 읽어서 Claude에게 그 안에서만 고르게 한다.
- 모임 주제 태그(`topic`, 처음 값은 AI, SF, 과학)는 책의 내용이 그 주제와 직접 관련되거나 그 주제의 모임 도서로 다룬 경우에 붙인다.
- 갈래 태그(`kind`)는 소설, 인문, 역사 같은 책의 종류다.

## 책 식별

- ISBN-13이 있으면 ISBN으로 같은 책을 찾는다.
- 같은 작품의 다른 판본(양장본, 개정판 등)은 ISBN이 달라도 작품 키로 묶는다. 작품 키는 괄호 속 판본 표기와 부제를 뺀 제목에 대표 저자를 붙여 정규화한 값이다.
- 책마다 같은 책을 찾는 키(작품 키와 ISBN)를 `book_keys`에 모은다. 다른 표기나 다른 판본 ISBN으로 찾은 키도 더하고, 관리자가 고치거나 합쳐도 예전 키를 남긴다.
- ISBN을 확정하지 못한 책도 작품 키로 저장하고, 나중에 ISBN을 찾으면 채운다.

## 운영 환경

|---|---|

| 이미지 | Artifact Registry `abc-library` 저장소(웹은 `asia-southeast1`, 배치는 `asia-northeast3`). 최근 5개만 남긴다 |
| 실행 일정 | Cloud Scheduler `abc-batch-daily`가 매일 03:00(KST)에 Job을 실행한다. Job이 실패하면 Cloud Monitoring이 메일을 보낸다 |

## 로컬 개발

| 구성 요소 | 위치 |
|---|---|
| DB | `compose.yaml`의 `postgres:18`(`localhost:5433`, DB `abc_library`). 운영과 같은 정렬 규칙(builtin `C.UTF-8`)으로 만든다 |
| 데이터 | `make db-seed`가 넣는 가상의 데모 데이터(`cmd/batch/seed.go`). `make batch-local`로 실제 밴드 글을 넣을 수도 있다 |

- `.envrc`는 운영 값을 담고, 로컬 개발 명령은 Makefile의 `LOCAL_DB`로 `DB_URL`과 `DB_PWD`만 바꿔 쓴다. 로그인 설정과 Claude API 키는 `.envrc`의 값을 그대로 쓴다.
- `make db-up`은 DB를 띄우고 마이그레이션을 적용한다. `make web`, `make test-integration`, `make db-seed`, `make batch-local`이 먼저 부른다.
- `batch seed`는 `DB_URL`이 이 컴퓨터(`localhost`, `127.0.0.1`, `::1`)를 가리킬 때만 실행한다.

## 배포

Google Cloud 프로젝트 `abc-library-512606`(이름 abc-library)에 배포한다. 2026-10-24에 `benelog` 프로젝트에서 옮겼다. 값은 `scripts/gcp-env.sh`에 있다.

| 구성 요소 | 이름 |
|---|---|
| 웹 서버 | Cloud Run 서비스 `abc-library`, 서비스 계정 `abc-web`, 최소 인스턴스 0, 공개 접근 |
| 일일 배치 | Cloud Run Job `abc-batch`, 서비스 계정 `abc-batch`, 2 vCPU, 2GiB, 제한 시간 1시간, 재시도 없음 |
| 비밀 값 | `db-pwd`(웹, 배치), `band-state`(배치, `/secrets/band/band-state.json`에 파일로 올림), `claude-api-key`(배치), `google-client-secret`, `session-secret`, `user-id-secret`(웹) |
| 실행 계정 | `abc-scheduler`(Job 실행), `abc-deployer`(GitHub Actions 배포) |

처음 한 번은 `.envrc`를 읽은 셸에서 다음 순서로 실행한다. 모두 다시 실행해도 된다.

```bash
make gcp-setup                  # API, 저장소, 서비스 계정, 비밀, GitHub Actions WIF
make band-secret                # band-state.json을 Secret Manager에 올림
make deploy-web deploy-batch    # 이미지 빌드, 푸시, 배포(DB_URL도 이때 설정)
make gcp-schedule               # 매일 실행과 실패 알림
make firebase-hosting           # https://abc-lib.web.app을 웹 서비스에 연결
```

`make firebase-hosting` 전에 Firebase 콘솔에서 이 프로젝트에 Firebase를 한 번 추가해야 한다(약관 동의와 Blaze 요금제 확인). Firebase 프로젝트를 지우면 GCP 프로젝트 전체가 지워지므로 지우지 않는다.

그 뒤에는 `main`에 push하면 GitHub Actions가 배포한다. 환경 변수와 비밀 값 연결은 서비스와 Job에 남아 있어서 워크플로는 이미지만 바꾼다.

- 밴드 세션이 만료되면 Job이 실패하고 알림 메일이 온다. `make band-login` 뒤에 `make band-secret`을 실행한다. Job은 비밀의 최신 버전을 읽으므로 다시 배포하지 않아도 된다.
- Claude API 키를 바꾸려면 `gcloud secrets versions add claude-api-key --data-file=-`로 새 버전을 올린다.
- 웹 서버는 `robots.txt`와 `X-Robots-Tag: noindex`로 검색엔진 수집을 막는다.
- 웹 서버는 마이그레이션을 적용하지 않는다. 스키마를 바꾼 코드를 push하기 전에 `make migrate`로 운영 DB에 먼저 적용한다. 그렇지 않으면 배포된 웹 서버가 다음 배치 실행까지 오류를 낸다.

### 로그인 설정

Google OAuth 클라이언트는 콘솔에서 사람이 한 번 만든다.

1. Google Cloud 콘솔의 **Google 인증 플랫폼**에서 `abc-library-512606` 프로젝트를 고른다.
2. **브랜딩**: 앱 이름(ABC 도서관), 사용자 지원 이메일, 승인된 도메인 `web.app`을 넣는다.
3. **대상**: 사용자 유형을 외부로 두고 앱을 게시한다(범위가 `openid`, `email`뿐이라 검증이 필요 없다). 사용자 로그인은 `openid`만, 관리자 로그인은 `openid email`을 요청한다.
4. **클라이언트**: 웹 애플리케이션 클라이언트를 만들고, 승인된 리디렉션 URI에 `https://abc-lib.web.app/auth/callback`(로컬에서도 쓰려면 `http://localhost:8080/auth/callback`)을 넣는다.
5. 나온 클라이언트 ID를 `scripts/gcp-env.sh`의 `GOOGLE_CLIENT_ID`에 넣는다.
6. `GOOGLE_CLIENT_SECRET=<보안 비밀> make gcp-setup`으로 `google-client-secret`, `session-secret`, `user-id-secret` 비밀을 만들고 `make deploy-web`을 실행한다. 이미 있는 비밀은 새 버전을 올리지 않는다.

그 뒤 GitHub Actions 배포도 같은 값을 쓴다. `GOOGLE_CLIENT_ID`를 비우고 배포하면 로그인 없이 뜬다. `scripts/deploy.sh`는 `user-id-secret`을 연결하므로, 이 비밀이 없는 프로젝트에 배포하기 전에 `make gcp-setup`을 먼저 실행한다.
- Cloud Run 앞단의 Google Frontend가 정확히 `/healthz`를 가로채므로 상태 확인은 `/health`로 한다.
